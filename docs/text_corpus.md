# Text corpus (SCRUM-23)

Generated by `python3 src/build_text_corpus.py` from `data/processed/youtube_comments_clean.csv`; re-running it with the same inputs gives the same CSV files. Do not hand-edit.

## Outputs

- `data/processed/text_corpus.csv`: one row per unique comment of a product (**29,189 rows**).
- `data/processed/text_corpus_by_product.csv`: one row per registry product (60 rows): comments, usable comments, tokens, top 10 terms.
- `data/processed/text_cleaning_report.csv`: counts for every step below.
- `docs/figures/text_top_terms.png` and `docs/figures/text_tokens_per_comment.png`.

## Method

1. **Extraction.** Only rows from each product's active query version are used (as in `clean_youtube.py`). Rows with empty text are dropped; nothing else is dropped. A comment seen in several snapshots is kept once, from its earliest snapshot (key `(product_id, comment_id)`). One video can be in several products' search results, so the same comment can belong to several products: it is kept once **per product**, and `n_products_sharing` says how many share it. Deduplicating on `comment_id` alone would remove one product entirely. `text_raw` is the cleaned table's text, unchanged.
2. **`text_sentiment_ready`** (for sentiment): HTML leftovers removed, lowercased, URLs and @mentions removed (an `@` followed by a letter; `@7:28` timestamps stay), characters repeated 3+ times cut to 2 (`sooo` -> `soo`, `!!!!` -> `!!`; digits are never collapsed), whitespace collapsed. Stop-words, negations (`not`, `no`, `never`), punctuation and emojis are **kept**.
3. **`text_clean`** (for topic modelling): from `text_sentiment_ready`, apostrophes joined (`don't` -> `dont`), video timestamps removed, then tokenized with the regex `(?:[^\W_]|[\u0900-\u0963\u0966-\u0DFF])+` (runs of letters and digits, Latin and Indic scripts). Emojis and punctuation therefore fall away. Digits-only tokens and stop-words are removed, **except registry brand and model tokens**, which are always kept (for example `nothing`, `find`, `15`, `s25`, `pro`, `ultra`). `tokens` holds the same words as `text_clean` (space-joined) and `n_tokens` their count.
4. **Flags (rows kept).** `is_emoji_only` and `likely_non_english` come from `clean_youtube.py`; `is_empty_after_clean` (no token left) and `is_too_short` (fewer than 3 tokens, empty included) are new. `is_usable` is true when none of the four is set. The model step filters on these.

Stop-words (`config.TEXT_EXTRA_STOP_WORDS`): sklearn's `ENGLISH_STOP_WORDS` (318 words, no download) plus
- Hinglish (30): hai, hain, ka, ki, ke, ko, ne, se, mein, nahi, nhi, bhai, yaar, kya, ye, yeh, vo, wo, bhi, hi, toh, tha, thi, aur, ho, kar, ek, koi, kuch, sab
- contraction leftovers and chat shorthand (23): dont, doesnt, didnt, isnt, wasnt, arent, werent, cant, couldnt, wont, wouldnt, shouldnt, im, ive, youre, youve, theyre, thats, theres, whats, lets, u, ur

## Read before using

- Comments are top-level only, from each product's 5 most-viewed sampled videos, in YouTube's relevance order, at most 100 per video. They are a narrow sample, not all comments about a phone.
- `likely_non_english` judges the script, not the language: Hinglish and other romanised Indian languages count as English, so an English-only sentiment model will misread many usable comments. The Hinglish stop-word list only helps topic modelling.
- Many comments are generic ("nice video", "first"); topic models may need a domain stop-list on top.

## ⚠️ Leakage warning for SCRUM-24

**The comments were collected on 2026-10-04** (the 10 pilot products also on 2026-10-03), as a relevance-ranked sample of the videos that were most viewed **by then**. Any per-day text feature built from `published_at` (comment counts, sentiment, topic shares per day) therefore reflects what had become popular by October, not what was visible on that day: a past day only has comments that survived into the October sample. **Text features must not be used as time-series predictors for earlier dates** without stating this caveat; treat them as product-level descriptors, or rebuild them from snapshots collected on (or before) each date.
